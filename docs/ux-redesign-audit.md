# MoTrend UX & Product Redesign Audit (Phase 0)

> **Статус**: Phase 0 — Аудит текущего состояния, карты пользовательского пути и защитного периметра функционала.  
> **Продуктовая метафора**: **Editorial Video Casting** — пользователь выбирает вирусную видеосцену, загружает одно фото своего лица и становится главным героем этой сцены.  
> **Дата аудита**: 21 сентября 2026 г.  
> **Окружение**: Production Web (`https://trend.moads.agency`), Static Frontend (`motrend`), Backend/Platform API (`moads-platform`).

---

## 1. Верифицированные наблюдения за реальным продуктом

### 1.1 Архитектура и стек фронтенда
- **Стек**: Чистый нативный JavaScript (ES2022 модули без сборщика и транспиляторов) + семантический HTML5 + чистый CSS в `<style>` внутри `public/index.html`.
- **Шрифтовая система**: Загружается кастомный веб-шрифт `Coolvetica` (`CoolveticaRg-Regular.woff`, `CoolveticaRg-Bold.woff`), с фоллбэком на `Arial, sans-serif`.
- **Цветовая палитра текущей версии**:
  - Фон (`--bg`): `#0b0b0b` (глубокий черный).
  - Карточки (`--card`): `#151515` (темно-серый контейнер).
  - Рамки (`--border`): `#2a2a2a`.
  - Текст (`--text`): `#ffffff`, второстепенный текст (`--muted`): `rgba(255, 255, 255, 0.70)`.
  - Единственный акцентный цвет (`--accent`): `#8BFFB0` (пастельный мятно-зеленый).
  - Ошибки: `#f87171` (пастельный кораллово-красный).

### 1.2 Каталог трендов и отображение данных
- **Эндпоинт каталога**: `GET /motrend/templates` (доступен публично без обязательной авторизации).
- **Фактические боевые шаблоны (проверено live-запросом)**:
  1. `yung_lean_storm2` ("Yung lean storm II") — 10 сек, 2 кр/сек, **стоимость 20 кредитов**, single-photo face swap, Storm II pipeline.
  2. `cwalk` ("C-Walk Dance") — 15 сек, 1 кр/сек, **стоимость 15 кредитов**, Kling v1.6.
  3. `guan_yin` ("Guan Yin Dance") — 15 сек, 1 кр/сек, **стоимость 15 кредитов**, Kling v1.6.
  4. `bella` ("Bella Trend") — 10 сек, 1 кр/сек, **стоимость 10 кредитов**, Kling v1.6.
- **Пользовательский кастомный референс**: Блок "Or use your own reference" (`customReferenceCard`), позволяющий загрузить произвольное видео `.mp4` / `.mov` (до 100 МБ) с биллингом пропорционально длительности видео (1 кредит/сек).
- **Карусель трендов**: Горизонтальный скролл-трек `.trendCarouselViewport` с 30%-м симметричным выглядыванием соседних карточек слева и справа, автовоспроизведением видео без звука (`muted`, `loop`, `playsinline`) и включением звука при клике.

### 1.3 Авторизация и профиль пользователя
- **Провайдер**: Firebase Authentication (Google OAuth popup / redirect fallback + Email/Password + сброс пароля).
- **Обработка сессии платформы**: После входа Firebase ID token обменивается через `POST /auth/session-login` на безопасную `HttpOnly` cookie-сессию `moads_session`.
- **Профиль и баланс**: Запрашивается через `GET /motrend/me`, возвращает `creditsBalance`, `country`, `language`, `supportCode`, `isAdmin`.
- **Хранение состояния**:
  - *Клиентское*: выбранный шаблон (`selectedTemplate`), файл фото (`rawFile`), превью фото (canvas blob), таймеры, состояние UI (открытие модалок, развернутые списки).
  - *Серверное*: баланс кошелька (`creditsBalance`), активные и архивные генерации (`jobs`), каталог шаблонов, платежные заказы.

### 1.4 Полный пайплайн генерации
1. Пользователь выбирает карточку тренда (или кастомный референс).
2. Выбирает фото через нативный инпут `<input type="file" id="filePhoto">`.
3. Клиент производит **локальную оптимизацию**: в памяти через `<canvas>` фото пропорционально даунскейлится до максимальной стороны 2048px и ступенчато сжимается в JPEG (качество 0.92 -> 0.85 -> 0.78 -> 0.70) до размера <= 12 МБ (исходный файл может быть до 40 МБ).
4. Нажатие кнопки "Generate" запускает:
   - Авторизационный барьер (если гость — мягко запрашивает вход через модалку).
   - Проверку баланса: если `creditsBalance < costCredits`, открывается кошелек с сообщением `"You are short X credits"`.
   - Резервирование задания: `POST /motrend/jobs/prepare` с `templateId`, `selectionKind` -> сервер возвращает `jobId` и безопасный `uploadPath` в Firebase Storage.
   - Прямая загрузка фото в Google Cloud Storage через Firebase Storage SDK (`uploadBytesResumable`) с трекингом прогресса.
   - Финализация создания: `POST /motrend/jobs/finalize` с `jobId` и `inputImagePath`. Сервер списывает кредиты, создает транзакцию в PostgreSQL и ставит Cloud Task в очередь.
   - Запуск поллинга: `GET /motrend/jobs` с адаптивным интервалом (2.5 сек при наличии активных задач, 10 сек в покое).
   - При завершении (`status === "done"`): показ кнопок `Prepare download` -> `Save video` / `Watch video` / `Share`.

## 2. UX-риски текущего интерфейса

| UX-риск | Описание проблемы | Влияние на конверсию и опыт |
| :--- | :--- | :--- |
| **Разорванная связь выбора сцены и фото** | Пользователь выбирает карточку в верхней карусели, после чего карточка просто подставляет текст в серый инпут внизу страницы (`Selected trend: Bella Trend (10 credits)`). Визуальный контекст видео теряется. | Теряется ощущение «кастинга»: пользователь забывает, в какую сцену он примеряет свое лицо. |
| **Слепой выбор фото** | Нативный файл-инпут `<input type="file">` показывает только текстовое имя файла (например, `IMG_3482.HEIC`). Нет превью загруженного лица. | Пользователь не уверен, то ли фото выбрано, хорошо ли оно откадрировано, перед тем как списать кредиты. |
| **Фейковые проценты прогресса** | Текущий таймер `computeEstimatedProgressPercent` линейно накручивает проценты до 99% на базе расчетного времени (10-20 минут). Если видео готово быстрее — скачок с 40% до 100%. Если задерживается — висит на 99%. | Вызывает раздражение и недоверие к надежности сервиса. |
| **Всплывающие модальные окна-алерты** | Подсказки по фото (`PHOTO_HINT_MESSAGE`) и предупреждения о нехватке кредитов всплывают в блокирующих алерт-окнах (`uploadHintModal`, `noticeModal`), перебивая флоу. | Пользователи закрывают модалки рефлекторно, не читая требования к фото. |
| **Технические идентификаторы в результатах** | В блоке "Your trends" выводятся сырые хэши (`8f2a1b… • done • ✅`), технические статусы и непонятная двухшаговая кнопка "Prepare download". | Интерфейс ощущается как внутренний dev-инструмент инженеров, а не премиальный потребительский продукт. |

## 3. Визуальные и UI-проблемы

1. **Монотонный «коробочный» лэйаут**: Страница представляет собой вертикальную стопку одинаковых прямоугольных блоков с серыми рамками (`.card { border: 1px solid #2a2a2a; }`). Отсутствует глубина, пространственная иерархия и фокус.
2. **Конкуренция кастомного референса**: Блок "Or use your own reference" занимает визуально столько же места, сколько вся лента трендов, отвлекая 90% пользователей, которые пришли просто примерить тренд.
3. **Разнобой типографики и кнопок**:
   - Размер кнопок жестко задан в 21px при базовом шрифте 19px.
   - Четыре разных класса кнопок (`.btn`, `.btn2`, `.btnRefresh`, `.btnDownloadPrimary`) с разными отступами, скруглениями и стилями ховера.
   - Отсутствие явных состояний `focus-visible` для доступности с клавиатуры.
4. **Неэффективное использование пространства на мобильных устройствах**: Слишком высокие заголовки шапки съедают первый экран; видеокарусель требует долгой прокрутки до кнопки генерации.

## 4. Отсутствующие, неясные или перегруженные текстом состояния

- **Критерии подходящего фото**: Сейчас спрятаны в длинном текстовом блоке алерта. Пользователь не видит наглядных визуальных примеров («Четкое лицо анфас, без очков и других людей в кадре»).
- **Сценарий нехватки кредитов**: Сейчас выдает алерт `You are short X credits` и кидает в модалку с пакетами без сохранения контекста выбранного тренда.
- **Статусы генерации**: Вместо абстрактных процентов пользователю нужны понятные этапы кинопроизводства:
  1. *Фото принято* (лицо успешно обработано);
  2. *Подготовка сцены* (синхронизация движения и света);
  3. *Создание финального видео* (рендеринг в высоком разрешении).
- **Возврат кредитов при сбое**: При технических ошибках внешних провайдеров система автоматически возвращает кредиты на баланс, но текущий текст в UI сухой: `Temporary generation outage (credits refunded). Fix in progress.`. Требуется спокойная человеческая формулировка с подтверждением сохранности баланса.

## 5. Что должно остаться нетронутым (надежное ядро продукта)

1. **Авторизационный движок**:
   - Логика авторизации через Firebase SDK (Google + Email).
   - Детекция Telegram In-App Browser (`isTelegramInAppBrowser`) и кнопка "Open in browser" для обхода ограничений Google OAuth внутри веб-вью.
   - Сессионный обмен кук с платформенным API (`/auth/session-login`, `/auth/session-logout`).
2. **Клиентский пайплайн сжатия изображений**:
   - Функция `prepareUploadImage(file)`: безопасное масштабирование через Canvas до 2048px, многоступенчатое сжатие JPEG, проверка `MAX_UPLOAD_IMAGE_BYTES` (40 МБ) и `TARGET_UPLOAD_IMAGE_BYTES` (12 МБ).
3. **Прямая загрузка в Google Cloud Storage**:
   - `uploadBytesResumable` напрямую из браузера в бакет `gen-lang-client-0651837818.firebasestorage.app`.
4. **Бэкенд-контракты и API**:
   - Все пути (`/motrend/templates`, `/motrend/me`, `/motrend/jobs/prepare`, `/motrend/jobs/finalize`, `/motrend/jobs/:id/refresh`, `/motrend/jobs/:id/prepare-download`, `/motrend/jobs/:id/share`, `/billing/credit-packs`, `/billing/orders/checkout`).
   - Модели данных, юнит-экономика, списание и возврат кредитов.
5. **Точная геометрия скролла карусели**:
   - Математика 30%-го выглядывания соседних карточек и симметричный «воздух» по краям контейнера.
